# Migration step → v1.4.1

**From:** `v1.4.0`
**To:** `v1.4.1`
**Release date:** 2026-08 (latest stable at time of writing)

---

## Summary

v1.4.1 is a security and bug-fix release on top of v1.4.0, plus one new
operator command.  It is the final step of the currently documented path.

## Key changes

- **New operator command** — `reactivate_workspace_member <workspace-slug> <email>`
  restores a deactivated workspace member without editing the database by hand.
  Run it inside the API container:

  ```bash
  docker compose exec api python manage.py reactivate_workspace_member <slug> <email>
  ```

- **Workspace modules API** now returns member IDs per module.
- **Bug fixes** — self-hosted notification loading (missing trailing slash),
  module member filtering, layout dropdown clipping, crashes on deleted labels,
  empty/unexpected API responses, exports list, profile activity, sub-work-items.
- **Security**
  - Published Space asset uploads now clamp the requested policy size to the
    instance `FILE_SIZE_LIMIT`.
  - `cryptography` → 50.0.0 (PKCS#7 Bleichenbacher oracle).
  - React Router → 7.18.1 (DoS, open redirect, XSS, constructor injection).
  - `sharp` → 0.35.3 (libvips fixes).
  - Further advisories resolved in `fast-uri`, `js-yaml`, `linkify-it`,
    `postcss`, `undici`, `sanitize-html`, `valibot`, `body-parser`.

## Migration considerations

- **No breaking environment-variable or topology changes** — the Compose files
  work unchanged.
- If you expose **published Space pages** with uploads, the server now enforces
  `FILE_SIZE_LIMIT` on those upload policies too — review the value in `.env`.

## Verification after the step

```bash
./setup.sh status
curl -s http://127.0.0.1:8080/api/instances/ -o /dev/null -w "%{http_code}\n"  # 200
docker compose images   # confirm all plane images are tagged v1.4.1
```
