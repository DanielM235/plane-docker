# Migration step → v1.3.0

**From:** `v1.2.3`
**To:** `v1.3.0`
**Release date:** 2026-04-06

---

## Summary

v1.3.0 is a large visual and functional refresh ("a cleaner, calmer Plane")
plus a security hardening pass.  No image renames or service-topology changes:
the Docker Compose services in this repository are unchanged.

## Key changes

- **Visual redesign** — spacing, colours, themes, design tokens, headers and
  breadcrumbs reworked across the whole product.
- **Gitea authentication** — new OAuth provider for self-hosted Gitea.
- **Timezone per workspace** — new timezone selection; projects default to the
  workspace timezone.
- **Instance-not-ready UI** revamped.
- **File upload hardening** — file validation to prevent malicious uploads;
  Markdown attachments allowed.
- **Security fixes**
  - Server-side enforcement of API-token rate limits (previously modifiable).
  - SSRF validation of webhook URLs (IP address checks).
  - `X-Frame-Options` header added to the upstream nginx configuration.
  - `IssueBulkUpdateDateEndpoint` scoped to workspace and project.
- **Bug fixes** — CSV-injection sanitisation on exports, plus a broad set of
  UI/UX corrections.

## Migration considerations

- **No breaking environment-variable changes** for this step.  The Compose
  files continue to work as-is.
- Database migrations run automatically via the `migrator` container.
- The upstream nginx now adds `X-Frame-Options`.  This repository's
  [`nginx/templates/plane.conf.template`](../nginx/templates/plane.conf.template)
  already sets `X-Frame-Options SAMEORIGIN`, so no action is required — the
  two are compatible.
- If you use **webhooks pointing at internal/private addresses**, note that
  SSRF validation is tightened from this release onward (further tightened in
  v1.3.1 with `WEBHOOK_ALLOWED_IPS`).
