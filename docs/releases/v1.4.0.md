# Migration step → v1.4.0

**From:** `v1.3.1`
**To:** `v1.4.0`
**Release date:** 2026-07 (latest minor at time of writing)

---

## Summary

v1.4.0 is the biggest step in this path: it upgrades the **Django framework
from 4.2 to 5.2** and ships a very large coordinated security batch.  It also
changes where instance logs are stored.

## Key changes

- **Framework upgrade — Django 4.2 → 5.2.**  The API layer moves to Django 5.2.
  Let the `migrator` run (it does automatically) and expect a slightly longer
  first boot.
- **New REST features** — "Lite List" endpoints for projects/members/cycles/
  modules; webhook payloads now include `workspace_slug`.
- **Telemetry** — self-hosted telemetry now reports via OTLP **metrics**
  instead of traces.
- **Logs moved into PostgreSQL** — instance logs are stored in the database
  with per-log-type retention, so log tables no longer grow unbounded.
- **Frontend i18n** — translations moved to per-feature JSON namespaces
  (`react-i18next`); no consumer-facing change.
- **Security (large batch)** — cross-workspace access-control scoping (IDOR
  fixes), deactivated-account/bot-account login blocking, API tokens stored as
  SHA-256 hashes instead of plaintext, HTML sanitisation with `nh3`, `order_by`
  allow-lists, SSRF hardening for webhooks/links/avatars, removal of the
  publicly known default `SECRET_KEY`/`LIVE_SERVER_SECRET_KEY` in the
  all-in-one/CLI manifests.

## Migration considerations

- **Django 4.2 → 5.2** is a major framework jump.  This repository runs
  migrations through the one-shot `migrator` service, which is the correct
  path — do **not** skip the migration step.
- **Log storage changed.**  If you had out-of-band tooling that tailed
  container logs for audit, note that instance logs are now persisted in
  PostgreSQL and pruned by retention.
- **Real client IP** — upstream fixed a typo so nginx now reads
  `X-Forwarded-For` correctly.  This repository's nginx template already sends
  `X-Forwarded-For`, so rate limiting / logs will see real client IPs.
- **Bot user emails** are now derived from `WEB_URL` — verify `WEB_URL` is
  correct before/after upgrading.
- **Webhook SSRF** is tightened further: redirects are no longer followed and
  the IP guard blocks multicast/unspecified/CGNAT/IPv4-in-IPv6 ranges.  Use
  `WEBHOOK_ALLOWED_IPS` (see the v1.3.1 notes) for internal webhook targets.

## Verification after the step

```bash
./setup.sh status
curl -s http://127.0.0.1:8080/api/instances/ -o /dev/null -w "%{http_code}\n"  # 200
docker compose logs migrator | tail -20   # confirm Django 5.2 migrations applied
```
